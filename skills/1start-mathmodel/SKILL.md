# 数学建模工作流

本 skill 是数学建模竞赛项目的总控入口。它不替代后续阶段 skill，而是负责启动流程、询问偏好、记录决策、生成计划，并按顺序调用各阶段 skill。

## 数学建模规范参考

如需领域判断，读取 `../_references/math_modeling_norms.md`。该文件只提供数学建模基本规范和防错知识，不改变本 skill 的阶段顺序和产出约定。

## 必须产出

在当前工作目录中创建或更新以下文件：

- `plan.md`：整体流程方案、建模方向、阶段顺序、预期产物和风险控制。
- `todo.md`：具体待办事项列表，记录每个阶段的任务和状态。
- `reports/RESUME.md`：最近一次可恢复进度、产物与证据、未完成事项、运行条件及下一步。首次制定计划后创建，执行中按下述规则更新。

## 进度保存与跨设备接续

本 skill 通过项目内文件交接进度。文件传输由用户或已授权的同步方式完成；它不自动同步设备、迁移会话或恢复进程。

- 启动时先执行“0. 识别新建或恢复”，再决定后续步骤；恢复项目不重新套用模板覆盖已有计划和待办。
- 首次创建交接记录、恢复已有项目，或用户要求暂停、换设备、交接时，读取 [进度保存与恢复协议](references/resume.md)。将其保存时机和交接要求带入本轮下游阶段任务。
- 主 agent 在可检查的子任务完成、关键决策或输入变更、长任务启动前及结束后、阶段切换和正常暂停前更新 `reports/RESUME.md`；先保存产物，再更新待办和交接记录。中断无法预告时只能恢复最近已落盘进度，不声称保存了未写入内容。
- `plan.md` 保存偏好与决策，`todo.md` 保存阶段和子任务状态，`reports/RESUME.md` 索引当前恢复点及证据；详细推导和运行结果仍保存在对应阶段报告中。

## 按需多 agent 协作

主 agent 负责阶段调度、文件整合、计划更新和返工。协作设置沿用用户最新明确指示或 `plan.md`，未指定时使用 `auto`，无需为默认设置再次提问：

- `single`：不创建子 agent，由主 agent 执行。
- `auto`：在 `2analysis-modeling` 存在关键假设、候选方法分歧或可独立核验的数据问题，或在 `6verity` 完整验收中存在可独立分工的审查范围时，按需委派。简单修改与依赖尚未确定的任务保持单 agent。
- `multi`：在上述两个阶段使用真实子 agent，人数与任务相匹配。默认最多同时 3 个子 agent，受用户设置和宿主实际并发限制约束。

进入上述阶段前，主 agent 按需读取 [协作协议与角色职责](references/multi-agent.md)，使用实际可用的子 agent 工具执行委派，等待所需结果并按证据整合。子 agent 的独立首稿冻结后，满足协作协议的触发条件时，主 agent 按协议启动有界的结构化交叉质询；未满足触发条件时，不为展示协作而强行讨论。第一版保持阶段顺序，`3coding-visual`、`4drawio`、`5writing` 仍由指定负责人顺序执行。子 agent 只执行自己的任务包，不递归招募或重新启动完整工作流。

工具不可用、并发资源不足或部分任务失败时，按协作协议记录真实执行方式并继续可完成的工作；不得把单 agent 的多角色叙述记为独立复核。子 agent 自报完成不能代替主 agent 检查产物与验收证据。

## 工作流

### 0. 识别新建或恢复

先检查 `plan.md`、`todo.md`、`reports/RESUME.md` 和现有阶段产物。存在计划、待办、交接记录或阶段产物时，按恢复协议核对项目身份、输入版本、产物完整性、验证证据和本机所需环境，确定最早需要继续或返工的任务；仅有题目和原始数据时按新项目处理。

恢复时只补齐缺失记录，保留有效产物和已明确的偏好；没有 `RESUME.md` 的旧项目也可从已有文件重建恢复点，无法证实的状态标为待核验。简要说明已确认完成的工作、下一步及阻塞项后，直接继续可执行任务。只有材料冲突或必要信息缺失且无法判定时询问，不为正常恢复重复征求确认。用户明确要求另开新项目时，使用独立目录保留原项目。

### 1. 读取并补齐用户偏好

规划前先读取当前会话中已明确的偏好，以及已有 `plan.md` 的“用户偏好”记录：

- 以用户最新的明确指示为准；会话中没有明确指示时，沿用 `plan.md` 的既有记录。
- 已确定的选项直接使用，不重复询问或要求确认。用户明确改选时，直接更新记录并沿用新选择。
- 只对缺失且会实质影响流程、无法从现有材料确定的偏好提问；记录存在冲突且无法根据用户最新指示消解时，只询问冲突项。

需要补齐时，按以下顺序处理：

1. **排版引擎**：Typst 还是 LaTeX？— 决定 5writing 使用哪套模板和编译命令。两套引擎均覆盖全部模板（14 中 + 3 英）。Typst 使用 `typst` 命令编译；LaTeX 使用 `xelatex` 命令编译（需跑两遍解决交叉引用）。没有既有选择且用户跳过询问时，默认使用 LaTeX。
2. **竞赛类型**：国赛/华为杯/华中杯/MCM/...— 决定模板选择，见 5writing 的模板族清单。
3. **论文语言**：中文/英文 — 优先使用用户明确指定或 `plan.md` 已记录的语言；均未确定时，MCM/ICM/COMAP 默认英文，其他默认中文。
4. **子问题数量是否已知**：影响章节文件生成数量。若未知，由 2analysis-modeling 阶段根据题面确定。

将确定的偏好同步到 `plan.md` 的“用户偏好”记录，默认值注明为默认选择，保留其他计划内容。后续阶段直接沿用这些偏好，除非用户明确改选或存在无法判定的冲突。


### 2. 制定方案

新项目按以下结构编写 `plan.md`；恢复项目仅更新缺失或变化部分：

```markdown
# 方案

要依次调用这些 skill，按照里面要求完成任务。

用户偏好：
- 排版引擎：<Typst / LaTeX>
- 竞赛类型：<国赛 / 华为杯 / MCM / ...>
- 论文语言：<中文 / 英文>
- 子问题数量：<已知 N 个 / 待分析确定>

协作设置：
- 模式：<auto / single / multi，默认 auto>
- 最大并行子 agent 数：<默认 3，按宿主可用并发下调>
- 启用阶段：2analysis-modeling、6verity
- 本轮实际分工与结果记录：<按需填写任务、角色、输入版本、输出路径、状态及降级原因>
- 结构化交叉质询：<未触发及原因 / 争议编号、质询与回应、仲裁证据及未决项>

workflow:
   step      skills
1. 赛题分析与建模设计 - `2analysis-modeling`
2. 编程实现和图表生成 - `3coding-visual`
3. 流程与架构图绘制 - `4drawio`
4. 竞赛论文撰写 - `5writing`
5. 验证和验收 - `6verity`
```

## 项目目录结构

各阶段按此骨架创建和填充文件：

```text
.
├── plan.md                      # 1: 本文件
├── todo.md                      # 1: 待办事项
├── reports/                     # 各阶段文档报告
│   ├── RESUME.md                    # 当前恢复点与跨设备交接记录
│   ├── ANALYSIS_MODELING_REPORT.md  # 1: 赛题分析-建模报告（2analysis-modeling）
│   ├── RESULTS_REPORT.md            # 2: 结果报告（3coding-visual）
│   ├── DRAWIO_REPORT.md             # 3: 非数据图说明（4drawio）
│   ├── VERIFY_REPORT.md             # 5: 验收报告（6verity）
├── code/                        # 2: 代码（3coding-visual）
│   ├── problem1.py
│   ├── problem2.py
│   ├── problem3.py               # 问题的数量应该更具题目动态调整
│   ├── ...
│   └── utils.py
├── results/                     # 2: 结果记录（3coding-visual）
├── figures/                     # 2+3: 所有图表（3coding-visual + 4drawio）
│   ├── *.pdf                    #     数据图 + 非数据图 PDF
│   ├── *.drawio                 #     非数据图源文件
├── paper/                       # 4: 论文（5writing）
│   ├── main.typ / main.tex      #     论文主文件（按用户选择的引擎）
│   └── sections/                #     各节文件（.typ 或 .tex）
```

方案必须明确每个阶段由哪个下游 skill 负责，以及该阶段应产出什么文件。

### 3. 生成待办

新项目将 `todo.md` 写成阶段性 checklist，格式如下；恢复项目保留已有任务及有效完成状态：

```markdown
# 待办事项

- [ ] 1. 赛题分析与建模设计 - `2analysis-modeling`
- [ ] 2. 编程实现和图表生成 - `3coding-visual`
- [ ] 3. 流程与架构图绘制 - `4drawio`
- [ ] 4. 竞赛论文撰写 - `5writing`
- [ ] 5. 验证和验收 - `6verity`
```

每完成一个阶段，都要更新 `todo.md` 中对应任务的状态。协作阶段由主 agent 汇总所需子任务并核对产物后再勾选；子任务输出按需保存在 `reports/agents/<阶段>/<轮次>/<任务>/`，总报告由主 agent 统一维护。

执行当前阶段时，按实际工作补充可检查的子任务；未完成子任务保持未勾选，并标注进行中、待核验或阻塞及原因。同步更新 `reports/RESUME.md` 的恢复点，避免阶段中途接续时只能整阶段重做。

### 4. 依次执行阶段

新项目按以下顺序调用下游 skills；恢复项目从核对后的首个未完成或失效任务继续，保留阶段依赖，仅重做受影响部分：

| 阶段 | Skill | 作用 | 主要产物 |
| --- | --- | --- | --- |
| 赛题分析与建模设计 | `2analysis-modeling` | 解析题意、识别变量/约束/数据/评价指标，并建立数学模型、目标函数、约束条件和求解策略。 | `ANALYSIS_MODELING_REPORT.md` |
| 编程实现和图表生成 | `3coding-visual` | 实现可复现代码，运行实验，生成结果表和多种多样的图表。 | `code/`, `results/` ,  `RESULTS_REPORT.md`, `figures/图表` |
| 流程与架构图绘制 | `4drawio` | 在论文确实需要时，绘制方法流程图、架构图和非数据型概念图。 | `figures/*.drawio`, `figures/*.pdf`, `DRAWIO_REPORT.md` |
| 竞赛论文撰写 | `5writing` | 基于分析、建模、代码结果和图表撰写最终竞赛论文，并按章节直接插入图表。 | `paper/` |
| 验证和验收 | `6verity` | 检查可复现性、一致性、产物完整性、格式规范和提交就绪状态。 | `VERIFY_REPORT.md` |

### 5. 验收失败后的返回与复验

读取 `reports/VERIFY_REPORT.md` 的结论和“返工任务”：

- `PASS`：本轮必需检查已实际通过，才勾选 `todo.md` 的验证和验收任务，并说明提交就绪。
- `FAIL`：按报告指定的负责 skill 返回对应阶段修复。不要仅因已经生成验收报告就视为完成，也不要为让论文数值对齐而擅改可信结果。
- `BLOCKED`：缺少工具、工具无法初始化、访问受限或缺少必要输入导致必需检查无法执行。记录缺少的条件，继续能独立完成的工作；条件具备后补跑检查。不得把说明阻塞原因等同于验收通过。

返工时在 `plan.md` 记录原因和返回阶段，将 `todo.md` 中需要修复的阶段、受影响的下游阶段和验收任务恢复为未完成。只重做受影响的任务：模型或计算结果变化时同步相关数据图、方法图和论文；仅修正路径或排版时不重跑模型。

返工、阻塞和最终验收结束后同步更新 `reports/RESUME.md`，记录受影响产物、证据有效范围及下一步；全部完成时写明当前验收结论和交付位置。

修复后再次执行 `6verity`，复验原失败项及受修改影响的检查；只复用对应产物未变化的既有通过证据，更新验收报告。当前产物仍有硬错误时保持 `FAIL`；无硬错误但必需检查未完成时保持 `BLOCKED`。同一问题没有新的修复依据或仍缺少外部条件时，记录已尝试方法和下一步所需条件，避免重复运行同一失败操作；仅在确实需要用户提供信息时询问。

## 阶段边界

- `3coding-visual` 负责生成所有依赖计算结果或实验输出的数据图表。
- `4drawio` 只负责概念图、算法流程图、架构图、路线图等非数据型图示。
- 不要让 `4drawio` 重复绘制 `3coding-visual` 已经生成的统计图或数据图。
- `5writing` 负责决定图表在论文中的位置，并按其“图片路径与编译目录”约定写入图表代码。图片路径、编译工作目录和引擎参数统一由 `5writing` 维护，入口不另列代码示例。
- 不要让 `5writing` 编造数值结论。论文中的数值必须来自 `RESULTS_REPORT.md`、结果表或已生成图表的数据。
