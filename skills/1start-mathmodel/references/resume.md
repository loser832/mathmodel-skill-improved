# 进度保存与恢复协议

本协议用于同设备中断恢复，以及同步项目目录后的跨设备接续。恢复依据是已保存的项目文件与可核验证据，不依赖旧聊天记录、内存、进程或子 agent 会话仍然存在。它不提供自动传输或跨设备并发写入协调。

## 保存恢复点

由主 agent 维护 `reports/RESUME.md`，子 agent 仅保存自己的任务产物并返回状态。首次制定计划后创建记录，并在以下边界更新：可检查的子任务完成、关键决策或输入改变、长任务启动前和结束后、阶段切换、阻塞、正常暂停及最终交付。不要等整个阶段完成才保存，也无需每次工具调用都写记录。

先写产物和日志，再更新 `plan.md` 中变化的决策及 `todo.md` 中任务状态，最后更新交接记录。保存交接记录时先完整写入同目录临时文件并在成功后替换正式文件；这只能降低单文件写坏的风险，不能保证整个目录或云盘同步是原子的，恢复时仍需交叉核对。新恢复点取代旧快照，尚未解决的问题和仍有效的证据链接应保留。

交接记录采用以下结构，字段写实际值；尚未执行或无法确认的内容明确说明，不填成完成：

```markdown
# 恢复与交接

- 更新时间：带时区的时间
- 项目标识：首次生成并沿用的标识，以及题目名称/来源；不要用本机绝对目录作身份
- 状态：进行中 / 已暂停 / 阻塞 / 已完成
- 当前阶段与子任务：对应 todo.md 的任务
- 恢复摘要：最近一个已验证完成点，以及中断位置

## 输入与版本
- 题目、数据、当前任务相关代码/配置及上游产物：项目相对路径与内容哈希或可核验的固定版本
- 项目 Git 提交（如有）及相关未提交修改；提交号不能代表未提交文件
- 使用的阶段 skills、共享 references 及模板版本：仓库版本或相关文件哈希；本机安装路径仅作参考

## 已完成与证据
| 任务 | 产物相对路径 | 输入/产物版本 | 已执行检查及证据位置 | 未验证范围 |
| --- | --- | --- | --- | --- |

## 未完成、失败与阻塞
- 待办任务、部分输出位置及可用范围；已尝试的方法、失败原因和继续所需条件
- 运行中或中断的作业/子任务：任务编号、原设备或会话、本轮输入、输出/日志、最后已知状态
- 可续算检查点（若程序确实支持）及适用条件；否则记录需要重跑的最小任务

## 运行条件
- 操作系统/终端、相关解释器/求解器/排版工具与依赖版本，依赖清单位置
- 命令工作目录（相对项目根）、实际命令、参数、随机种子、退出状态和日志路径
- 必需环境变量名与用途；密钥值不写入记录
- 外部输入/字体/工具的获取方式、版本及本机路径映射；未同步内容及影响

## 下一步
1. 首个可执行动作、输入与完成判据
2. 后续依赖与需补跑的验证

## 最近一次恢复核对
- 恢复设备/环境与时间、核对结果、复用或失效的证据及原因；未恢复过则注明
```

记录服务于当前任务，不要求每次扫描和哈希整个项目。至少标识原始题目/数据与本次复用或继续任务所依赖的文件；未变化文件可复用已核验的标识。依赖已有清单时链接该清单，详细实验和推导链接阶段报告，避免维护多份结论。

## 启动时恢复检查

1. **识别项目。** 读取计划、待办、交接记录和相关报告，核对题目/数据是否属于同一项目。用户最新明确指示优先；不要仅按修改时间选择相互冲突的记录。题目身份或关键版本冲突无法由材料判定时，先保留各版本并询问冲突项，继续不依赖该冲突的工作。
2. **核对产物与证据。** 依赖关系、输入/产物版本、文件完整性和实际验证证据共同决定可复用范围。勾选状态、文件存在、旧报告里的 PASS 或进程已启动都不能单独证明完成。未勾选但已有完整产物的任务先做必要核验，证据充分后补记完成；已勾选但产物缺失、输入改变或证据失效的任务恢复为待核验或待完成。仅重做受影响任务及其下游。
3. **兼容旧项目。** 缺少交接记录时从计划、待办、阶段报告和实际产物重建；缺少计划或待办时也只补缺失部分。无法证实的事项写“待核验”，不假造历史命令、验证或完成状态。更新进度前不套用新项目模板清空旧记录。
4. **检查本机环境。** 在真正执行对应任务前，检查该任务需要的 skills、共享 references、模板、数据、工具及依赖。使用当前项目根解析相对路径；原设备的绝对路径、盘符和进程标识仅作历史参考，发送新任务包时重新解析为本机绝对路径。缺少必要能力时记录具体阻塞并继续独立工作。换设备本身不使所有结果失效，但环境差异影响的计算、编译或验证应补查；skill 版本变化时核对其相关产物与验收规则差异。
5. **处理未完成作业。** 旧设备的进程和子 agent 不视为在本机仍运行，也不直接沿用旧会话标识。先检查已保存的输出和日志；只有程序确实支持且输入、配置和检查点匹配时才续算，否则重跑未完成的最小任务并保留可用输出。原设备作业可能仍写入共享文件且无法确认停止时，使用独立运行目录隔离新输出，核验后再整合，不启动向同一结果文件写入的重复作业。
6. **继续执行。** 在 `todo.md` 对齐子任务状态，在 `RESUME.md` 记录本轮核对、复用范围和下一步，简要向用户说明后直接执行。所有必需产物和验收已通过且仍适用时说明已完成，不重复启动全流程；必需检查缺失时按 `6verity` 的规则继续，不能把恢复成功等同于验收 PASS。

恢复多 agent 任务时，检查已落盘任务包、独立首稿、输入版本和证据，保持 `references/multi-agent.md` 的版本失效与审查独立性要求。仅重新安排缺失或失效的任务；主 agent 接管完成的检查不能记为独立复核。

## 暂停与换设备交接

- 用户要求暂停或换设备时，不再派发新增长任务；在可控范围内停止本轮作业或保存程序支持的检查点。无法停止或无法联系原设备时记录最后已知状态及输出位置，不声称已经停止，也不为等待长任务完成而延误交接。
- 将已有产物、部分进度、未完成任务、关键决策和下一步保存到上述文件。非正常退出没有机会补写时，新设备按最近记录和实际产物核对，不能承诺精确恢复到最后一条操作。
- 交接应包含题目/原始数据、`plan.md`、`todo.md`、`reports/`（含所需 agent 报告和日志）、`code/`、`results/`、`figures/`、`paper/`，以及实际使用的配置、依赖清单、模板和其他引用文件，保留相对布局。Git 或同步工具可能忽略数据与结果，需核对必要文件实际已传输；未传输内容在交接记录中列出。
- 新设备需要可发现且兼容的整套相关 skills 与共享资源，以及当前任务所需运行环境；技能不属于项目目录时需另行迁移或安装，不复制旧虚拟环境来代替环境配置。凭据在新设备单独配置。
- 默认按设备顺序交接。没有用户指定且可用的同步通道时只准备本地交接材料并说明待同步项，不声称另一台设备已经更新；只有实际完成传输和核对后才记录同步完成。保留不同设备产生的冲突版本，按证据整合，不按“最后修改者获胜”覆盖结果。
